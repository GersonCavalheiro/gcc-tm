Versão didática STM

Este programa distribui 400 operações por uma equipe OpenMP: 40 escritas e 360 leituras, relação 1:9. Cada escrita incrementa um contador. Cada leitura copia uma observação consistente para um objeto local que também é registrado, pois sua vida começou antes da tentativa. O número de threads solicitado é quatro; a contagem total não depende de o ambiente conceder toda a equipe.

#include <assert.h>

int main(void)
{
  int valor = 0;
  #pragma omp parallel for num_threads(4)
  for (int i = 0; i < 400; ++i)
    {
      if (i % 10 == 0)
        {
          #pragma omp transaction (valor)
          {
            valor += 1;
          }
        }
      else
        {
          int observado = 0;
          #pragma omp transaction (valor, observado)
          {
            observado = valor;
          }
          assert(observado >= 0 && observado <= 40);
        }
    }
  assert(valor == 40);
  return 0;
}

Compile obrigatoriamente no modo funcional. O corpo não usa critical; o protocolo STM protege todos os acessos concorrentes a valor. A asserção final ocorre após a barreira implícita do parallel for. O programa verifica o resultado, mas não exige uma quantidade de conflitos: o escalonador pode serializar as operações.

Relação com o exemplo parametrizado existente

O arquivo transaction_carga.c é um exercício maior da infraestrutura de rastreamento. Seu critical(transaction_carga_state) externo à diretiva protege os valores. O Makefile padrão usa -fopenmp, sem selecionar STM. Seus resultados não constituem uma medição de isolamento ou desempenho STM.

Na raiz do repositório:

make -C transaction_test check-carga CARGA_THREADS=4 CARGA_REPETICOES=1000
transaction_test/.build/transaction_carga 4 1:9 1000

Os argumentos são threads, pesos escritas:leituras e repetições por thread. Para N repetições e pesos W:R, cada thread realiza floor(N*W/(W+R)) escritas. O comando acima corresponde a 4.000 operações, 400 escritas e 3.600 leituras; o valor final é 400. O verificador também confere a consistência do agregado e a infraestrutura de registro/liberação.

Pesos e soma devem caber em uint32_t, com soma positiva. Threads e repetições devem ser positivas e o total deve caber em unsigned long long. Esse programa maior exige a equipe solicitada. O alvo check-carga cobre 1:9, 1:1 e 9:1; os logs ficam em transaction_test/.build/.

A versão didática fixa o total global em 400 para simplificar a leitura. Ela é um programa separado; não altera o significado nem os parâmetros do exercício original. Logs de depuração e tamanho reduzido também impedem interpretar esses exemplos como benchmark.

Há também uma versão maior com serviços privados, transaction_interno_carga.c, que usa STM real sem critical. Consulte serviços internos para sua forma de compilação e execução. Ela complementa a miniatura com diretiva mostrada neste capítulo.
