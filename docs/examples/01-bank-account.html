Índice · Compilação

Os dois programas são independentes. Compile com -fopenmp -fopenmp-transaction-stm usando o build local. As verificações ficam fora da transação. Os valores em centavos evitam introduzir arredondamento de ponto flutuante.

Depósito: um objeto

O saldo existe antes da tentativa e aparece na lista. O acesso de leitura e a escrita de += são instrumentados. Uma tentativa que falhe não deixa o depósito parcialmente aplicado.

#include <assert.h>

int main(void)
{
  int saldo = 10000;
  #pragma omp transaction (saldo)
  {
    saldo += 2500;
  }
  assert(saldo == 12500);
  return 0;
}

Transferência: dois objetos

A verificação de fundos e as duas atualizações pertencem à mesma transação. A soma permanece 12.000 centavos. Se não houver fundos, o bloco termina normalmente sem alterar as contas; essa decisão de negócio não é um conflito do runtime.

#include <assert.h>

int main(void)
{
  int origem = 10000;
  int destino = 2000;
  #pragma omp transaction (origem, destino)
  {
    if (origem >= 2500)
      {
        origem -= 2500;
        destino += 2500;
      }
  }
  assert(origem == 7500);
  assert(destino == 4500);
  assert(origem + destino == 12000);
  return 0;
}

Esses programas mostram a semântica básica, sem pretender provocar conflitos. O exemplo carga acrescenta acessos concorrentes. Mensagens ao usuário, gravação em arquivo e outras ações externas devem ocorrer depois da confirmação; não podem ser colocadas no corpo como se fossem desfeitas em retry.
