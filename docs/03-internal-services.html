Índice · Modelo

Duas interfaces diferentes

A ABI GOMP_transaction_stm_v1_* liga o código gerado à libgomp e está declarada no cabeçalho compartilhado. Os símbolos são exportados em GOMP_NEWTM_2.0. As primitivas newtm_* são internas, com visibilidade oculta; programas comuns devem usar a diretiva. Testes internos podem ligar o archive estático com os cabeçalhos privados apropriados.

O rastreamento usa os serviços separados GOMP_transaction_begin/register/end, em GOMP_NEWTM_1.0. Eles não substituem a ABI STM.

Tipos e convenções

newtm_status_v1 é uint32_t: NEWTM_ABI_OK=0, NEWTM_ABI_CONFLICT=1, NEWTM_ABI_INVALID=2. newtm_slot_v1 contém um ponteiro opaco para contexto. O slot é do chamador, começa nulo, tem endereço estável e não pode ser copiado como um segundo proprietário. O contexto passado aos serviços é emprestado.

newtm_binding_v1 contém object, object_size, offset e kind. newtm_clone_binding_v1 acrescenta storage, com REGISTERED ou PRIVATE. Esses descritores representam identidade, não propriedade de buffers ou referências. O layout usa alinhamento nativo do alvo; não é formato portátil de rede.

Serviços exportados

Todos os serviços abaixo têm prefixo GOMP_transaction_stm_v1_. ctx é um contexto vivo do chamador; slot é o endereço do slot canônico. Exceto fatal, os retornos são newtm_status_v1.

Serviço e argumentos Contrato principal
begin(newtm_slot_v1 *slot, uint32_t *outermost) Inicia tentativa; devolve indicação externa, mantém lease. Não registra objetos implicitamente
register(ctx, const void *object, size_t size, uint32_t kind) Registra identidade/tamanho; NEWTM_ABI_SCALAR ou NEWTM_ABI_AGGREGATE
read(ctx, const void *object, size_t offset, void *destination, size_t size) Reserva/lê faixa; consumir destino somente depois de OK
write(ctx, const void *object, size_t offset, const void *source, size_t size) Reserva/escreve faixa no buffer privado
status(ctx) Consulta a situação efetiva da tentativa
nest_begin(ctx) Entra em região plana sem transferir propriedade
nest_end(ctx) Sai da região interna sem commit externo
end(newtm_slot_v1 *slot) Confirma na saída externa; sucesso consome o contexto e zera o slot
fail(ctx, uint32_t cause) Condena sem limpar; INVALID prevalece, causa desconhecida/OK é inválida
discard(newtm_slot_v1 *slot) Consome tentativa não publicada; não faz retry por si só
after_failure(newtm_slot_v1 *slot, size_t attempt) Limpa todos os níveis; conflito faz backoff e retorna CONFLICT; INVALID termina fatalmente após limpar
fatal(uint32_t cause) Retorno void, noreturn; não limpa um contexto vivo

Objetos, slots e buffers precisam continuar válidos. Os buffers de entrada/saída devem ser independentes e viver durante a chamada. Falhas de acesso preservam a saída; um ponteiro pendente continua violando o contrato, mesmo se não for NULL. Falhas anteriores à publicação em end deixam os recursos disponíveis para o epílogo de falha.

Exemplo completo: controlador explícito de depósito

Este exemplo ensina o protocolo que normalmente é gerado pelo compilador. Não há diretiva no programa. Compile com o include gcc-src-tm/include, ligue à libgomp local com -lgomp -pthread e configure o rpath conforme o guia.

#include "newtm-abi.h"
#include <assert.h>
#include <stdint.h>

int main(void)
{
  int saldo = 10000;
  size_t conflitos = 0;
  for (;;)
    {
      newtm_slot_v1 slot = 0;
      uint32_t externa = 0;
      newtm_status_v1 s = GOMP_transaction_stm_v1_begin(&slot, &externa);
      if (s == NEWTM_ABI_OK && externa != 1)
        s = GOMP_transaction_stm_v1_fail(slot, NEWTM_ABI_INVALID);
      if (s == NEWTM_ABI_OK)
        s = GOMP_transaction_stm_v1_register(slot, &saldo, sizeof saldo,
                                            NEWTM_ABI_SCALAR);
      int valor = 0;
      if (s == NEWTM_ABI_OK)
        s = GOMP_transaction_stm_v1_read(slot, &saldo, 0, &valor, sizeof valor);
      if (s == NEWTM_ABI_OK)
        {
          valor += 2500;
          s = GOMP_transaction_stm_v1_write(slot, &saldo, 0, &valor, sizeof valor);
        }
      if (s == NEWTM_ABI_OK)
        s = GOMP_transaction_stm_v1_end(&slot);
      if (s == NEWTM_ABI_OK)
        {
          assert(slot == 0);
          break;
        }
      if (!slot)
        GOMP_transaction_stm_v1_fatal(s);
      s = GOMP_transaction_stm_v1_fail(slot, s);
      if (s == NEWTM_ABI_CONFLICT && conflitos != SIZE_MAX)
        ++conflitos;
      s = GOMP_transaction_stm_v1_after_failure(&slot,
                                               conflitos ? conflitos : 1);
      if (s != NEWTM_ABI_CONFLICT)
        GOMP_transaction_stm_v1_fatal(s);
    }
  assert(saldo == 12500);
  return 0;
}

O valor lido só é usado depois de OK. Cada tentativa recria valor; o contador de conflitos fica fora do contexto descartado. Se a entrada falhar sem contexto, usa-se fatal; se existir contexto, a saída passa por after_failure. Não se deve chamar fatal diretamente abandonando reservas vivas.

Variações didáticas do protocolo

Para cancelar voluntariamente uma tentativa ativa, a sequência é begin → register → write → discard, verificando cada retorno. Com saldo inicial 10.000 e escrita privada 12.500, um discard bem-sucedido deixa o saldo em 10.000. Ele não pede retry automaticamente.

Para aninhamento preparado, a sequência é begin → register → nest_begin → read/write → nest_end → end. As falhas internas retornam ao controlador externo. Não passe o slot proprietário a uma função que só deveria tomar o contexto emprestado.

Para uma faixa de agregado, registre a extensão canônica adequada e use deslocamento/tamanho em read/write. Não trate o endereço de um campo como autorização para acessar o objeto inteiro. Esses esquemas descrevem variações; não são programas completos nem dispensam o epílogo de falha demonstrado acima.

Primitivas privadas

Os contratos completos estão nos cabeçalhos hash, transação e contexto.

Família Primitivas Responsabilidade
Tabela newtm_hash_create, newtm_hash_destroy Criar; destruir somente com quiescência, preservando tabela em BUSY
Referências newtm_hash_acquire, newtm_hash_lookup_acquire, newtm_hash_release Reter por identidade; consulta sem inserção; liberar uma referência por aquisição bem-sucedida
Consultas newtm_hash_entry_address, newtm_hash_entry_size Ler propriedades imutáveis com referência viva
Metadados newtm_hash_entry_visit Callback sob mutex do bucket, sem espera/reentrada
Diagnóstico newtm_hash_count Contagem consistente saturada; não prova quiescência
Ciclo newtm_begin, newtm_register, newtm_end, newtm_fail, newtm_discard Propriedade, registro, publicação e descarte
Acesso newtm_reserve, newtm_read, newtm_write Reservas e valores privados
Controle newtm_after_failure, newtm_backoff, newtm_execute Limpeza/retry externo de corpos explicitamente preparados
Política newtm_policy_destroy Destruir metadados após retirada da última referência

Os enums de hash, acesso e ciclo de vida são contratos distintos; não faça casts para substituir traduções explícitas. Uma aquisição de hash exige exatamente uma liberação; copiar o ponteiro não retém outra referência. Um exemplo mínimo de uso conceitual é criar tabela, adquirir entrada, consultar endereço/tamanho, liberar e destruir após quiescência. Isso testa identidade e vida útil, não uma transação.

O callback de newtm_execute recebe contexto emprestado e deve registrar, verificar e propagar todas as falhas. Não pode consumir o slot externo ou escrever resultados especulativos em seu argumento estável: o controlador não desfaz essas escritas arbitrárias. Para exemplos executáveis das primitivas privadas, veja os alvos check-hash-* e check-lifecycle no guia de validação.

Exemplos completos existentes com a interface privada

Os fontes transaction_interno_simples.c e transaction_interno_carga.c demonstram corpos preparados manualmente com newtm_execute, registro e acesso privado. O segundo mantém o par value/inverse coerente sem critical. Seu argumento de controle é estável entre retries; os resultados são publicados no objeto registrado.

make -C transaction_test exemplos-internos
make -C transaction_test check-internos
transaction_test/.build/transaction_interno_carga 4 1:9 100

O Makefile compila OpenMP separadamente e liga o archive local sem acrescentar uma segunda libgomp dinâmica. Essa forma de ligação é necessária para os símbolos privados e difere do pequeno exemplo da ABI exportada acima.
