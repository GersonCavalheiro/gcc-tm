Implemented examples

Nine examples, four versions each: sequential.c (reference), internal.c (private services, or explicit exported ABI in example 08), directive.c (omp transaction), and gnu_tm.c (GNU TM).

  1. Deposit
  2. Transfer
  3. Concurrent counter
  4. Read/write workload
  5. Flat nesting
  6. Helper functions
  7. Aggregate and intervals
  8. Explicit ABI controller
  9. Compute-heavy transactions with an early write

Run from the repository root

make -C examples
make -C examples check
make -C examples/04-workload check
examples/04-workload/.build/directive 4 400 1 9

Each example has its own Makefile. Shared rules are in common/rules.mk. Version targets sequential, internal, directive and gnu_tm are also available in each example directory. Use make clean before changing build or flags.

The Makefiles select the local GCC, libgomp and libitm from gcc-build, without installation. The target is obtained from xgcc -dumpmachine. Override GCC_BUILD=/absolute/build/path for another build. GNU TM requires libitm to be built. The internal version links the local libgomp archive; dynamic versions use local library paths and rpath.

make check uses process timeouts, requires successful exits and a single RESULT line, and compares each implementation with the sequential reference. Additional counter/workload cases cover one and four requested threads, read-only/write-only workloads and 1:9, 1:1 and 9:1 ratios. Invalid input is checked too. Results and logs are retained in each .build/ directory, ignored by Git.

The sequential reference validates arithmetic and final results; it does not prove isolation, abort behavior or retry execution. All conflicting concurrent accesses use their selected transactional protocol. Ordinary final observations occur after synchronization. For timing comparisons, use the dedicated repeated-experiment protocol linked below; the tiny examples alone do not establish performance rankings.
