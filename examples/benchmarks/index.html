Repeated timing experiments

The counter and mixed read/write workload emit a TIMING line using CLOCK_MONOTONIC. Timing starts before the parallel region and stops after its barrier, including team startup and transaction/runtime initialization. Result checking and output are outside the interval. The actual thread count is checked. The sequential reference also emits timing, but is excluded from the requested three-way comparison.

Run the full experiment

python3 -m pip install -r examples/benchmarks/requirements.txt
python3 examples/benchmarks/run.py

Dependencies are NumPy, SciPy and Matplotlib. The script builds both examples, then runs 30 rounds of 144 configurations: counter and workloads with write:read weights 1:9, 1:1 and 9:1; 1,000, 10,000 and 100,000 total operations; 2, 4, 6 and 8 threads; directive, gcc_tm and internal. The gcc_tm label selects the gnu_tm executable. This is 4,320 measured runs plus 144 discarded warmups. Runs are sequential, with a fixed-seed randomized order per round. OMP_DYNAMIC=FALSE, OMP_PROC_BIND=close, OMP_PLACES=cores and OMP_WAIT_POLICY=PASSIVE are used consistently.

Each program now accepts up to 1,000,000 operations. Workload weights remain bounded by 1,000 and intermediate arithmetic uses long long to avoid overflow. Load size denotes total operations shared by all threads (strong scaling), not operations per thread. Each operation has deliberately small useful work and contention on one shared object.

Outputs

The first default run uses results/index.html. If results already exists, a fresh results-YYYYMMDD-HHMMSS directory is created automatically, with a numeric suffix if necessary. The selected directory is printed at startup; its index.html is generated after completion. raw.csv retains every timing and its randomized round/order. summary.csv provides mean, median, sample standard deviation, coefficient of variation, quartiles, range, throughput and bootstrap 95% mean intervals. comparisons.csv provides paired ratios, bootstrap intervals, Wilcoxon tests on log ratios and family-wise Holm-adjusted p-values. PNG and SVG time/CI and distribution plots are generated for each workload.

python3 examples/benchmarks/run.py --output examples/benchmarks/results-repeat
python3 examples/benchmarks/analyze.py examples/benchmarks/results

An explicit --output directory must not already exist; a clear usage error is shown otherwise. Without --output, a new directory is selected automatically. Previous measurements are never overwritten. --sizes accepts three values; --threads, --seed and --repetitions allow explicitly labeled alternative experiments. Do not treat small smoke runs as the full 30-round study.

Interpretation

All observations are retained, including outliers. Confidence intervals are pointwise bootstrap intervals from 5,000 resamples. Ratios above one mean the numerator is slower. Read effect size and uncertainty before p-values. Randomized rounds reduce ordering bias but cannot eliminate machine drift or shared-host noise. No guaranteed conflict count or general performance superiority follows from these workloads. The fresh-process design includes cold runtime initialization: warmups warm the machine, not persistent runtime state. Small loads may be dominated by startup.

Raw results are checked against independent expected final values; invalid output, incorrect team size, trace logs or process failure abort the study. Binary hashes, environment and CPU information are recorded in metadata.json. Generated results are ignored by Git; archive them separately when publishing.
